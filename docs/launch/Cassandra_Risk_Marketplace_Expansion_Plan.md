# Cassandra-Risk Marketplace Expansion Plan

Date: March 31, 2026

## Purpose

This document turns the post-launch marketplace discussion into an execution
plan for Cassandra-Risk distribution beyond RapidAPI.

It separates:

- commercial marketplaces
- discovery networks
- performance/credibility directories

It also distinguishes what appears to be:

- self-serve and fast
- curated and slower
- visibility-only rather than direct monetization

## Current State

Cassandra-Risk is already live on:

- [RapidAPI](https://rapidapi.com/umran-jkXU3nEmi/api/cassandra-risk-governed-macro-fragility-signal-api)
- [GitHub](https://github.com/umran-n/cassandra-risk-replication)

The next goal is wider distribution without losing:

- product clarity
- pricing discipline
- operational control
- research-backed positioning

## Recommended Execution Order

1. Zyla API Hub
2. Postman API Network
3. APILayer
4. APIContext / API.expert

This order reflects actual onboarding friction and likely speed to impact,
not just brand appeal.

## Channel-by-Channel Findings

### 1. Zyla API Hub

Status: `High priority / immediate`

Best role:

- secondary commercial marketplace
- paid distribution
- organic developer discovery

Why this comes first:

- Zyla appears to support direct provider onboarding and API publication
- provider-facing messaging is explicitly monetization-first
- the current Cassandra pricing and hard-limit setup fits the platform well

What official sources say:

- Zyla says providers can publish APIs for free and start monetizing
- they advertise `80%` revenue share
- they advertise `1-Click Postman Import`
- they emphasize `SEO + AI Maximum Visibility`
- they currently allow APIs with a `Hard Limit`
- they require a minimum uptime of roughly `99.8%`
- payouts are processed via `PayPal`

Official sources:

- [Zyla monetize page](https://www.zylalabs.com/monetize-your-api)
- [Zyla homepage](https://zylalabs.com/)

Implication for Cassandra:

- Cassandra is already structured in the right shape for Zyla:
  - monthly plans
  - hard limits
  - clear endpoint catalog
  - marketplace-ready branding

Recommendation:

- mirror the RapidAPI listing to Zyla first
- keep the same public positioning
- keep the same price anchor for the first pass

### 2. Postman API Network

Status: `High priority / immediate`

Best role:

- developer discovery
- public documentation
- SEO surface
- product onboarding

What official sources say:

- Postman allows public APIs to be published by making a workspace public
- public workspaces and collections become available on the Postman API Network
- Postman explicitly frames the API Network as a large public discovery layer

Official sources:

- [Publish your public APIs to the Postman API Network](https://learning.postman.com/docs/postman-api-network/showcase/publish/public-apis)
- [Publish overview](https://learning.postman.com/docs/postman-api-network/showcase/publish/overview/)
- [Discover public APIs on the Postman API Network](https://learning.postman.com/docs/getting-started/first-steps/exploring-public-api-network/)

Implication for Cassandra:

- Postman is not the same kind of monetization layer as Rapid or Zyla
- it is still highly valuable because it improves:
  - discoverability
  - developer trust
  - quickstart experience
  - search index presence

Recommendation:

- create a public Cassandra-Risk workspace
- publish a public collection covering the six public endpoints
- include:
  - endpoint descriptions
  - quickstart request examples
  - DOI links
  - GitHub repo link
  - RapidAPI listing link

### 3. APILayer

Status: `Strategic / submission-driven`

Best role:

- curated commercial marketplace
- fintech / utility API exposure
- additional paid distribution

What official sources say:

- APILayer does accept external providers
- providers submit via the provider application flow
- APIs are reviewed and curated rather than instantly listed
- providers host their own APIs
- providers set their own pricing
- APILayer explicitly states provider listings are non-exclusive
- payouts are handled monthly
- as an individual provider, payout goes to the given bank account

Official sources:

- [APILayer Provider FAQ](https://marketplace.apilayer.com/docs/article/provider-faq)
- [APILayer Marketplace FAQ](https://marketplace.apilayer.com/docs/article/marketplace-faq)

Important notes from the source:

- APILayer is “carefully curated”
- descriptions should preferably stay under `250 words`
- they want:
  - explanation of how the API works
  - official sources or certifications if applicable
  - sample request and response
  - use cases

Implication for Cassandra:

- this is not the fastest listing, but it is worth pursuing
- the `non exclusivity` language is a very useful finding for Cassandra’s
  wider marketplace strategy
- Cassandra will likely need a tighter APILayer-specific pitch rather than
  a full long-form marketplace copy dump

Recommendation:

- prepare an APILayer submission pack
- treat it as a reviewed application, not a same-session duplicate launch

### 4. APIContext / API.expert

Status: `Visibility / monitoring / credibility`

Best role:

- performance visibility
- monitoring-based credibility
- directory presence

What official sources indicate:

- API.expert is tied to public API monitoring collections and performance views
- APIContext operates an API directory centered on ratings and performance
- neither source clearly presents itself as a self-serve commercial marketplace

Official sources:

- [API.expert documentation](https://docs.apimetrics.io/docs/apiexpert)
- [APIContext API Directory](https://apicontext.com/api-directory/)
- [APIContext main site](https://apicontext.com/)

Implication for Cassandra:

- these should not be treated as “copy the Rapid listing and publish”
- they are better viewed as:
  - monitoring inclusion targets
  - directory inclusion targets
  - infrastructure credibility layers

Important caveat:

- the impressive Rapid screenshot metrics are useful for marketing
- but APIContext / API.expert appear to rely on their own monitoring systems
- so Cassandra would likely need:
  - active monitoring
  - directory inclusion
  - or direct outreach

Recommendation:

- treat these as phase-two credibility channels
- pursue after Zyla and Postman are live

## Commercial / Terms Notes

### Verified

- APILayer explicitly states provider listings are **non-exclusive**

Source:

- [APILayer Provider FAQ](https://marketplace.apilayer.com/docs/article/provider-faq)

### Not Yet Verified

- Zyla exclusivity or price-parity language
- APIContext inclusion terms
- API.expert inclusion terms

Operational conclusion:

- do not assume every commercial listing channel is non-exclusive
- before duplicating paid plans across multiple commercial marketplaces, do a
  quick terms review for:
  - exclusivity
  - parity clauses
  - revenue-share obligations
  - payout timing
